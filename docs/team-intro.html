협업 방식

How we worked

01 규칙 문서 하나가 유일한 기준

게임 규칙은 docs/SPEC.md 하나에만 적고, 코드와 어긋나면 문서가 맞다. 섹션 번호를 코드 주석이 직접 참조해 규칙이 바뀌면 고칠 코드가 검색 한 번에 나온다.

02 어기면 게임이 깨지는 열 가지

팀 규칙을 CLAUDE.md 에 열 개만 못 박았다. 예: AI의 자리를 밖으로 내보내지 않는다, 진행 판정에 클라이언트 시계를 쓰지 않는다, 쓰기는 전부 서버를 거친다.

03 기능별 브랜치와 PR

기능마다 브랜치를 파고 리뷰 후 합쳤다. 커밋 메시지는 「무엇을 왜」를 한국어 한 줄로 쓰고 근거 섹션을 붙여, 히스토리만 읽어도 결정 이유를 따라갈 수 있다.

04 검사를 사람 눈에 맡기지 않음

규칙과 화면은 자동 테스트로, DB 동작은 흉내가 아니라 실제 Postgres에 물어본다. 멀티플레이는 배포 후 소켓 두 개를 실제로 왕복시켜 확인한다.

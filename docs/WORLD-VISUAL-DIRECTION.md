# 3D 월드 비주얼 디렉션 — 씬 아트 · 스포트라이트 · 스크린 주제 UI

작성: UI/UX. 대상 파일은 **원상 소유**(`app/world/warehouse.tsx`, `world-scene.tsx`)라
여기서는 **의도·수치·연출만** 정한다. 실제 구현은 원상에게 넘긴다.

이 문서의 모든 제안은 한 문장을 통과해야 한다 —
**"이 연출로 어느 자리가 봇인지 골라낼 수 있나?"** 골라낼 수 있으면 그 연출은 버린다 (I1).
게임이 도는 방에서는 조명·말풍선·반응이 **사람과 봇에게 완전히 같은 규칙**으로 걸려야 한다.

## 0. 지금의 톤 (유지할 것)

읽어 본 씬은 이미 좋은 방향이다. 바꾸지 말고 **더 밀어붙일** 기준선이다.

| 요소 | 현재 값 | 성격 |
|---|---|---|
| 배경색 / 안개 | `#080604` / `fogExp2 #0b0805 0.028` | 거의 검은 갈색. 깊이는 안개가 만든다 |
| 톤매핑 | ACES Filmic, exposure 1.1 | 하이라이트가 부드럽게 뭉개진다 (시네마틱) |
| 키 컬러 | 앰버 `#ffe3bd` · `#ffd9ac` · `#d4a373` | 백열등/텅스텐. **따뜻한 쪽 하나로 통일돼 있다** |
| 악센트 | 붉은 대기등 `#ff3320` (toneMapped=false) | 유일한 한색 대비. 무대턱·비상등 |
| 재질 | roughness 0.6~1.0, metalness 낮음 | 무광 산업 재질. 반사가 튀지 않는다 |

**한 줄 요약: "전원 내린 공연장의 텅스텐 예열."** 이 정체성을 세 연출 모두가 지킨다.
차가운 UI 블루·형광 그린 같은 걸 새로 들이지 않는다 — 이 방의 유일한 한색은 붉은 표시등이다.

## 1. 스크린 주제 노출 UI

### 1-1. 무엇을 고치나

지금 스크린은 `카운트다운(20→0) → 영상`뿐이다 (`ScreenVideo`, `ScreenCountdown`).
게임이 시작되면 **그 판의 주제(질문)**가 이 스크린에 떠야 한다. 스크린은
- 16:9, 폭 10 · 높이 5.625, 중심 `y=4.2`,
- 스폰 원이 스크린을 보고 시작하므로 **모두의 첫 시선이 여기 꽂힌다**.

이 자리는 방에서 가장 밝고 가장 큰 면이다. 주제를 여기 띄우는 건 옳다.

### 1-2. 렌더링 방식 — 기존 패턴을 그대로 확장

`ScreenCountdown`이 쓰는 **2D 캔버스 → `CanvasTexture` → `meshBasicMaterial toneMapped=false`**
경로를 그대로 쓴다. 3D 폰트 로더(troika)를 새로 들이지 않는다 — 숫자와 같은 이유.
캔버스는 `1024×576`(16:9)을 유지한다. HUD가 아니라 **스크린에 직접** 그리는 게 핵심이다:
시선이 이미 거기 있고, "이 방의 사건은 저 화면에서 벌어진다"를 공간으로 가르친다.

### 1-3. 3단 시퀀스 — "정전 → 점등 → 각인"

주제 공개는 정보 전달이 아니라 **의식(ritual)**이다. 3.2초를 쓴다.

```
t=0.0s   ▸ 암전     스크린이 딥 브라운(#0b0906)으로 눌린다. 스크린 스포트 3개가
                    0.25초에 걸쳐 intensity 190 → 40 으로 죽는다 (아래 2-2 "주제 히트")
t=0.4s   ▸ 라벨     상단에 작게 "오늘의 주제" — letter-spacing 넓게, 앰버 55% 투명
t=0.8s   ▸ 본문     주제 텍스트가 blur(8px→0) + opacity(0→1) 로 0.5초간 맺힌다
t=1.3s   ▸ 각인     스포트 3개가 40 → 210(평소보다 살짝 오버) 로 튀며 텍스트를 때린다
                    이 순간 스크린 emissive 도 0.14 → 0.22 로 짧게 부풀었다 돌아온다
t=3.2s   ▸ 정착     텍스트 유지, 조명 210 → 190 평상값으로 안착
```

핵심은 **t=1.3s의 "각인"**이다. 어두웠다가 빛이 텍스트에 꽂히는 0.1초 —
카메라 노출(ACES)이 이미 하이라이트를 물고 있어서, 이 순간 글자 테두리가 하얗게
번지며 눈에 박힌다. 페이드인만 하면 밋밋하고, 이 "빛으로 때리기"가 극장 느낌을 만든다.

### 1-4. 타이포 · 레이아웃 (캔버스 좌표 1024×576 기준)

```
┌──────────────────────────────────────────────┐
│                                              │  ← 상단 여백 90px
│            오 늘 의  주 제                     │  ← 라벨 34px, tracking +0.35em
│                                              │     color rgba(212,163,115,0.62)
│   ────────────────────────────────           │  ← 구분선 폭 360px, 앰버 25%, 두께 2px
│                                              │
│      "재택근무, 진짜 효율적일까?"              │  ← 본문 최대 72px, 줄당 ~14자
│                                              │     bold, #f0e4d0, 2줄까지 자동 줄바꿈
│                                              │
│                                              │  ← 하단 여백에 진행 힌트 (선택, 1-6)
└──────────────────────────────────────────────┘
```

- **본문 폰트 크기는 글자 수로 자동 축소**한다. `fontSize = clamp(44, 72, 폭÷글자수)`.
  주제가 길어도 잘리거나 넘치지 않게. 2줄 넘어가면 44px 하한에서 멈추고 3줄 허용.
- **폰트**: `bold ... ui-sans-serif, system-ui` — 카운트다운과 동일 스택. 새 폰트 없음.
- **색**: 본문 `#f0e4d0`(따뜻한 오프화이트). 순백(`#fff`)은 이 방에서 뜬다 — 톤이 깨진다.
- **따옴표로 감싼다** — "주제"임을 활자로 알린다. 라벨이 안 보여도 질문임이 읽힌다.

### 1-5. 배경 처리 — 글자만 남기고 화면을 죽인다

주제가 뜨는 동안 스크린 배경은 **완전 단색이 아니라 아주 옅은 비네트**를 준다:
중심 `#12100c` → 가장자리 `#080604`, radial. 순수 평면이면 "정지 화면"처럼 죽어 보이고,
미세한 명암 그라디언트가 있으면 "빛나는 막"으로 살아난다. 캔버스 `createRadialGradient`
한 줄이면 된다.

### 1-6. 페이즈별 스크린 상태 (선택 — 워커가 페이즈를 알아야 함)

`docs/MULTIPLAYER.md §8`은 "워커가 페이즈를 알기 시작하는 것"을 경계한다. 그래서
**주제 텍스트는 워커가 아니라 클라이언트가 Supabase에서 직접 읽어** 스크린에 그리는 쪽을
권한다 (게임 규칙은 이미 Supabase 권위). 스크린 표시는 아래 4상태로 충분하다.

| 페이즈 | 스크린 | 조명 |
|---|---|---|
| lobby | 카운트다운 → 소개 영상 (지금 그대로) | 평상 스포트 |
| 주제 공개 | 위 3단 시퀀스 → 주제 고정 | "주제 히트"(2-2) |
| question/chat | 주제 상단 축소 고정 + 하단에 남은 시간 바 | 평상 |
| vote | 주제 흐려지고 "지목하세요" | "집중"(2-3) |

**남은 시간은 스크린 하단의 얇은 가로 바**로 준다 (앰버, 왼→오 소진). 숫자 카운트다운은
초조함만 키운다. 색은 유지하고 **끝 3초에만** 붉은 대기등 색(`#ff3320`)으로 물들여
"곧 끝"을 방 전체가 같은 순간에 느끼게 한다. — 시계는 표시용, 판정은 서버(I2).

## 2. 스포트라이트 · 라이팅 연출

### 2-1. 지금의 조명 구조 (기준선)

- **스크린 스포트 3개**: `from y=6.6` → `to y≈3.3`, angle 0.4, intensity 190, `#ffe3bd`.
  레퍼런스의 "세 갈래 빛 웅덩이".
- **좌석 다운라이트 2개**: intensity 80, `castShadow`(그림자는 이 둘만 굽는다).
- 펜던트 9개(절반만 광원) + 벽 브래킷 4개 + 앰비언트/헤미.

프레임 예산이 빡빡하다("전부 켜면 프레임 반토막"). 그래서 **새 광원을 늘리지 않고,
있는 스포트의 intensity/색을 시간에 따라 흔드는 것**만으로 연출을 만든다. 이게 싸고 안전하다.

### 2-2. "주제 히트" — 스크린 스포트 펄스 (1-3과 물린다)

주제가 각인되는 t=1.3s에 스크린 스포트 3개를 `190 → 40 → 210 → 190`으로 움직인다.
- 죽이는 구간(→40)은 ease-out 0.4s, 때리는 구간(→210)은 ease-**in** 0.12s(빠르게 꽂힘),
  안착(→190)은 0.6s. **비대칭 이징**이 "탁!" 하는 타격감을 만든다.
- 3개를 **10ms씩 스태거**해서 좌→우로 훑고 지나가게 하면 정적인 동시 점등보다 살아난다.

구현은 `Spot`의 intensity를 `useFrame`에서 시각 기반으로 lerp. 펜던트 flicker와 같은 패턴.

### 2-3. "집중(vote)" — 방을 좁힌다

투표 페이즈엔 **주변 광을 낮춰 스크린과 좌석만 남긴다**. 봇을 가리키는 게 아니라
방 전체를 어둡게 눌러 긴장을 만든다.
- 펜던트 `26 → 14`, 벽 브래킷 `11 → 6`, 앰비언트 `0.22 → 0.15`. 스포트는 유지.
- 안개를 `0.028 → 0.034`로 살짝 짙게 — 공간이 좁아지는 체감.
- 전환 1.5초 ease-in-out. **급격히 어두워지면 "누가 스위치 내렸다"가 되고,
  천천히 조이면 "분위기가 무거워진다"가 된다.**

### 2-4. 좌석 스포트 — ★ I1 절대 경계

지금 좌석 다운라이트는 **자리(x,z)에 고정**돼 있다. 이건 안전하다.
**절대 하면 안 되는 것**: "말하는 사람에게 스포트를 이동/점등"하는 연출.

> 봇의 발화는 서버가 조종하고 타이밍 분포가 특정 자리에 쏠리지 않게 공들여 맞춰 놨는데
> (`MULTIPLAYER.md`의 speakAt/pendingText 분리), 발화자에게 조명이 따라붙으면 **그 공들인
> 타이밍이 조명으로 다시 새어 나온다.** 화자 추적 스포트 = 봇 색출기. 넣지 않는다.

발화 강조가 정 필요하면 **말풍선(3절)에서만** 하고, 조명은 자리와 무관하게 둔다.
좌석 조명을 굳이 움직이려면 **모두를 동시에** 밝히거나 낮춘다 (예: vote 때 전원 살짝 up).

### 2-5. 마이크로 디테일 (싸고 효과 큰 것들)

- **먼지 기둥(god rays 대용)**: 스크린 스포트 3개 안에 아주 옅은 원뿔 반투명 메시
  (`#ffe3bd`, opacity 0.03~0.05, additive). 볼류메트릭 없이 "빛기둥"을 만든다.
  이 방의 안개와 만나 공기가 보인다. **삼각형 몇 개**라 공짜에 가깝다.
- **붉은 대기등 호흡**: 무대턱 `#ff3320` 4개를 `sin`으로 opacity 미세 변동(0.7↔1.0).
  "장비에 전원이 들어와 있다"는 생명감. 지금은 완전 정적.
- **펜던트 flicker는 이미 훌륭하다** — 두 사인 겹쳐 규칙성 지운 것. vote 때 진폭만 키우면
  "전압이 흔들린다" 긴장으로 재활용된다.

## 3. 한 줄 반응 표시

### 3-1. 지금 (기준선)

`RemoteAvatar`가 아바타 머리 위 `Html`로 **말풍선 + 닉네임**을 띄운다.
- 말풍선: `bg-black/80`, `ring-white/15`, 13px, 최대 220px, `bubbleUntil`까지 표시.
- 닉네임: 좌석 색(`seatColor`), `bg-black/60`, 11px.

이건 "긴 대사"용이다. 요청한 **"한 줄 반응"**은 이것과 **다른 레이어**로 본다:
대사(문장)와 리액션(즉각 반응)은 성격이 다르다.

### 3-2. 두 층으로 나눈다

| | 대사 (기존 말풍선) | 반응 (신규) |
|---|---|---|
| 내용 | 문장 — "재택은 집중이 안 돼서요" | 짧은 리액션 — "ㅋㅋㅋ", "동의", "글쎄…", 👍 |
| 계기 | 채팅 입력 / 봇 발화 | 남의 말에 대한 즉각 반응 |
| 지속 | ~4초, 읽는 시간 | ~1.8초, 튀어올랐다 사라짐 |
| 위치 | 머리 위 정면(빌보드) | 머리 위 **살짝 옆/위**, 대사와 안 겹치게 |
| 모양 | 둥근 사각 말풍선 | 알약(pill) / 이모지 단독 |

### 3-3. 반응 모션 — "팝 앤 페이드"

```
0.00s  scale 0.6, opacity 0, y offset 0      아래에서
0.14s  scale 1.12, opacity 1                 오버슈트(살짝 큼) ← back-ease-out
0.28s  scale 1.0                             정착
~1.5s  유지 (살짝 위로 6px 부유)
1.8s   opacity 1→0, y +14px                  위로 흩어지며 사라짐
```

오버슈트(1.12배 튀었다 돌아옴)가 "즉각성"의 핵심이다. 선형 페이드인은 반응처럼 안 보인다.
`Html`의 div에 CSS `@keyframes` + `animation` 하나로 끝난다 (three 애니메이션 불필요).

### 3-4. 색 · 형태

- 배경 `bg-black/70`, 텍스트는 **좌석 색**(닉네임과 같은 `seatColor`) — 누구 반응인지 색으로 읽힌다.
- 이모지 반응은 배경 없이 **글리프 단독** + 옅은 그림자. 12~16px.
- 알약 반응은 `rounded-full px-2.5 py-0.5 text-[12px] font-semibold`.
- **순백 배경/네온 금지.** 방 톤(2절)과 같은 어두운 반투명 위 좌석색. UI만 붕 뜨면 몰입이 깨진다.

### 3-5. ★ I1 경계 — 반응도 신호가 된다

말풍선과 똑같은 함정이 반응에도 있다. `MULTIPLAYER.md`가 이미 다룬 규칙을 **시각 쪽에서도** 지킨다:

1. **반응 중에도 발이 멈춘다.** 사람은 리액션을 띄우는 순간 `composing`으로 발이 묶인다.
   봇도 발화 직전 `anim='idle'`로 서야 한다(이미 그렇게 함). 반응 레이어를 새로 만들 때
   **봇만 걸어가며 반응하면 그 자리가 봇**이다. 반응 표시 = 정지, 예외 없음.
2. **반응 빈도·확률에 자리별 편차가 없어야 한다.** "항상 즉각 반응하는 자리 = 봇".
   봇은 이미 `BOT_REACT_CHANCE`/쿨다운으로 아껴 반응한다 — **시각 레이어가 이걸 우회하는
   경로(예: 사람 반응은 100%, 봇 반응은 확률)를 새로 만들면 안 된다.** 같은 파이프를 탄다.
3. **반응 지연(readDelay)을 시각적으로 드러내지 않는다.** "타이핑 중…" 점 3개 같은 인디케이터를
   봇에게 다르게 주면(예: 사람만 표시) 그게 신호다. 주려면 모두에게, 안 주려면 아무에게도.

### 3-6. 겹침 방지

한 사람 위에 대사(3-1)와 반응(3-3)이 동시에 뜰 수 있다.
- 대사는 `y=2.0`(현재), 반응은 `y=2.5`쯤 **위로** 올려 세로로 쌓는다.
- 반응이 여러 개 연속이면 **최신 하나만** 보여주고 교체(큐 X). 머리 위가 팝콘밭이 되면 안 된다.
- `distanceFactor`로 멀면 작아지는 것 유지. 단 반응은 대사보다 `distanceFactor`를 조금 크게
  줘서 멀어도 "무슨 반응인지"는 읽히게(이모지는 특히).

## 4. 구현 우선순위 (원상에게 넘길 때)

| 순 | 항목 | 난이도 | 근거 |
|---|---|---|---|
| 1 | 스크린 주제 3단 시퀀스 (1-3,4,5) | 중 | 첫 시선이 꽂히는 곳. 체감이 가장 크다 |
| 2 | 주제 히트 스포트 펄스 (2-2) | 하 | 1과 물려야 완성. intensity lerp만 |

# 게임 화면 UI — 발언 순번 · 단계 타이머 · 투표 · 최후변론

작성: UI/UX. 대상은 게임 화면(`app/room/[code]`, `components/room-view.tsx` — **C 소유**).
여기서는 **레이아웃·상태·모션·색만** 정한다. 구현은 C에게 넘긴다.

이 화면의 모든 UI는 두 관문을 통과한다.
- **I2 — 타이머는 표시용이다.** 남은 시간은 서버 `phase_ends_at`(ISO)에서만 유도한다.
  클라 시계로 페이즈를 넘기지 않는다. 아래 §1이 이걸 컴포넌트로 강제한다.
- **I1 — 어느 자리가 봇인지 새면 안 된다.** 순번·타이머·투표·변론 어디에도 "봇만 다른"
  상태가 생기면 안 된다. 특히 §2(발언 순번)와 §5(최후변론)가 위험 지점이다.

> ⚠️ **SPEC 재조정 필요** (§7에 모아둠). 요청에 나온 **발언 순번**과 **최후변론**은
> 현재 SPEC §18 상태머신에 **없다.** **자유대화 60초**도 SPEC의 `chat 120초`와 다르다.
> 이 문서는 요청안대로 그리되, A(상태머신 소유)가 §18을 고쳐야 실제로 돈다.

## 0. 화면 골격 (모든 페이즈 공통)

```
┌───────────────────────────────────────────────────────────┐
│  ● 방코드 KMQT      [ 단계 타이머 ]           AI 1 · 자리 5 │  ← 상단바 (고정)
├───────────────────────────────────────────────────────────┤
│                                                           │
│                    ▛ 페이즈 본문 ▟                         │  ← 페이즈별 교체
│                  (주제 / 자유대화 / 투표 / 변론)            │
│                                                           │
├───────────────────────────────────────────────────────────┤
│  [ 발언 레일 — 좌석 순번 ]                                  │  ← 하단 레일 (고정)
└───────────────────────────────────────────────────────────┘
```

- **상단바·발언 레일은 페이즈가 바뀌어도 자리를 지킨다.** 본문만 교체된다 — 페이즈가
  넘어갈 때 화면 전체가 리셋되면 "지금 몇 명이 어디 있나"의 감각이 끊긴다.
- **AI 수·자리 수는 상단 우측에 상시 노출**한다. §18 규칙상 "AI가 몇인지"는 공개값이다.
  단 **어느 자리인지는 절대 표기하지 않는다** (I1) — 숫자만.

### 디자인 토큰 (Space Grotesk 기반, 다크 포커스 UI)

## 1. 단계 타이머 — `PhaseTimer` (I2의 뼈대)

### 1-1. 동작 규칙 (디자인이 강제하는 계약)

```
remainingMs = phase_ends_at(ms) − serverNow()
serverNow() = Date.now() + serverOffset   // offset은 입장 시 한 번 측정해 캐시
```

- **표시만 한다.** 0에 닿으면 `POST /api/phase/advance { expected_seq }`를 **한 번** 쏘고
  (I6), 화면을 스스로 넘기지 않는다 — 서버가 전환을 브로드캐스트하면 그때 넘어간다.
- 0 이하에서 멈춘 채 "정산 중…"을 보여준다. 클라 시계가 빨라 먼저 0이 돼도 페이즈는
  서버가 넘길 때까지 그대로다 (I2의 증상: "시계 3초 빠른 사람만 먼저 넘어감" — 이걸 막는다).
- `phase_ends_at === null`(lobby)이면 타이머를 **아예 렌더하지 않는다**. 무기한이다.

### 1-2. 두 가지 형태

**(A) 상단바 링/바 — 항상 보이는 것**

```
  주제  ●───────────────○     0:47
        └ 진행 바 (왼→오 소진)
```
- 라벨(주제/자유대화/투표/변론) + 얇은 진행 바 + `분:초`.
- 색: 평소 `#ff8a3d`. **남은 10초부터 `#ff4d4d`로** 물들고 바가 1초 주기로 맥동(opacity 0.6↔1).
- 진행 바는 `transform: scaleX`로만 움직인다(리플로우 없음). transition-linear.

**(B) 조기 종료가 있는 페이즈의 보조 표기**

question·vote는 "전원 제출/투표"로 일찍 끝난다 (§5.2). 이땐 시간 옆에 **진행 카운트**를 단다.

```
  주제  ●──────────○  0:31      제출 3 / 4
```
- **"3 / 4"의 분모는 `is_bot=false and connected`인 사람 수**다 (I5, §18.6). 봇을 세면
  시작하자마자 4/4가 되어 페이즈가 0초에 끝난다 — 그럼 봇 수가 드러난다.
- 이 카운트는 **누가** 냈는지 표시하지 않는다. 숫자만. 자리별 체크표시는 §2 레일에서만.

## 2. 발언 순번 표시 — `SpeakingRail`

### 2-1. 무엇인가

하단 고정 레일. 좌석을 순번대로 늘어놓고, **주제 단계에서 답변이 도착하는 순서**를 보여준다.
"지금 누구 차례인가 / 누가 아직인가"를 한눈에.

```
 ┌─ 발언 레일 ────────────────────────────────────────────┐
 │  ①익명1 ✓   ②익명2 ✓   ③익명3 ◍현재   ④익명4 ·   ⑤익명5 ⌀│
 └────────────────────────────────────────────────────────┘
    └색:seatColor   ✓=도착   ◍=지금 차례(주황 펄스)   ·=대기   ⌀=이탈(connected=false)
```

- 각 칩: `동그란 좌석번호(seatColor) + 닉네임 + 상태 아이콘`.
- **정렬은 좌석 번호 고정.** 도착 순으로 재정렬하지 않는다 — 자리가 튀면 시선이 흔들리고,
  무엇보다 "봇이 항상 몇 번째로 도착" 같은 패턴이 정렬로 드러날 수 있다.
- connected=false(mock의 익명5)는 흐리게(`#5b6474`) + `⌀`. 조기 종료 분모에서 빠졌음을 암시.

### 2-2. ★ I1 — 순번은 가장 새기 쉬운 곳이다

발언 순번/도착 타이밍은 봇 색출의 1순위 신호다. 아래를 **디자인 계약으로** 못 박는다.

1. **도착 표시는 서버 `visible_at`에만 맞춘다.** 답변은 페이즈 시작에 한꺼번에 생성되고
   `visible_at`에 시각이 박혀 지연 노출된다 (§5.3). 레일의 `✓`도 **그 시각에** 켜진다 —
   실제 타이핑이든 봇이든 클라는 `visible_at`만 본다. **봇에게만 다른 지연/즉시 표시를
   만들지 않는다.**
2. **"입력 중…" 인디케이터를 자리별로 주지 않는다.** 사람은 타이핑 상태가 있고 봇은 없으면
   그 차이가 곧 봇이다. 주려면 **모두 같은 규칙**(예: `visible_at` 도래 전 N초를 일괄
   "작성 중"으로 표기)이고, 안 주려면 아무에게도 안 준다. **기본은 안 준다** — 가장 안전.
3. **"현재 차례(◍)"는 순번의 페이싱 표시일 뿐 강제가 아니다.** 특정 자리가 자기 차례에
   0초 만에 항상 도착하면 신호다. `visible_at`의 지터가 사람/봇 동일하게 걸리는 한 안전하고,
   레일은 그 지터를 **그대로** 반영만 한다(앞당기거나 늦추지 않는다).

> 요약: **레일은 `visible_at`의 거울이다.** 자체 판단으로 순서·타이밍을 만들지 않는다.
> 이 원칙 하나면 §2의 I1 위험이 전부 닫힌다.

### 2-3. 자유대화(chat) 단계에서의 레일

자유대화엔 정해진 순번이 없다(자유 채팅, §5.2 chat). 레일은 **발화량 점**으로 바뀐다.

```
 │  ①익명1 •••   ②익명2 •   ③익명3 ••••   ④익명4 —   ⑤익명5 ⌀│
```
- 각 자리의 점 개수 = 그 페이즈 채팅 수(상한 4, `••••`). **횟수만, 내용/시각 아님.**
- 이것도 I1 주의: "한 번도 안 친 자리 = ?" 같은 추론을 부추기지 않게, 0회는 `—`로
  중립 표기하고 색을 죽인다. 봇도 사람도 침묵할 수 있음을 UI가 자연스럽게 전제.

## 3. 단계별 본문 — 주제 · 자유대화

### 3-1. 주제 (question, 60초)

```
        ┌──────────────────────────────────────┐
        │  공통 질문 · 1라운드                    │  ← 라벨 (보조색)
        │                                       │
        │   "재택근무, 진짜 효율적일까?"          │  ← 질문 (28px bold)
        │                                       │
        └──────────────────────────────────────┘

   ┌─ 도착한 답변 (visible_at 순으로 아래에 쌓임) ─────────┐
   │  ①익명1  음 글쎄                                    │
   │  ②익명2  나는 그런 상황이면 일단 자리를 뜰 것 같다     │
   │  ◍ 익명3 · · ·                          (도착 대기)   │
   └─────────────────────────────────────────────────────┘

   ┌─ 내 답변 ───────────────────────────────────────────┐
   │  [ 여기에 한 줄 답하기…              ]      [ 제출 ]  │
   └─────────────────────────────────────────────────────┘
```

- 답변 카드는 **좌석번호(seatColor) + 닉네임 + 텍스트** 한 줄. 도착하면 **위로 밀며 fade+slide**
  (120ms, ease-out). 새 답변이 항상 목록 하단에 붙어 "지금 막 왔다"가 읽힌다.
- 내 입력창은 제출 후 잠긴다("제출됨 ✓", 청록). **재제출 불가**. 조기 종료 분모(§1-2 B)에 반영.
- 2라운드(question 2)는 라벨만 "2라운드"로. 같은 레이아웃 재사용.
- **질문 텍스트는 B의 질문 풀에서 온다** (mock의 `questions[].text`). UI는 비어도 깨지지 않게
  스켈레톤 한 줄을 둔다.

### 3-2. 자유대화 (chat)

> ⚠️ 요청은 **60초**, SPEC §5.2는 **chat 120초**다. §7에서 재조정. 아래는 시간과 무관한 레이아웃.

```
   ┌─ 대화 ──────────────────────────────────────────────┐
   │  ③익명3  2번 방금 문장 왜 이렇게 반듯함                │
   │  ②익명2  ㅋㅋㅋ 원래 이럼                             │
   │  ...                                     (자동 스크롤) │
   └─────────────────────────────────────────────────────┘
   ┌─────────────────────────────────────────────────────┐
   │  [ 채팅…                              ]      [ 전송 ] │
   └─────────────────────────────────────────────────────┘
```

- 표준 채팅 UI. 내 말은 오른쪽 정렬 없이 **좌석색 강조**로만 구분(정렬을 바꾸면 봇/사람
  레이아웃이 갈릴 여지가 생긴다 — 전부 왼쪽 정렬 + 색 구분으로 통일).
- 메시지도 `visible_at` 순. 봇 답변 지연은 이미 서버가 시각에 박아 보낸다(§5.3).
- **끝 10초에 하단에 "곧 투표가 시작됩니다" 배너**가 슬라이드업. 다음 단계 예고 = 마음의 준비.

## 4. 투표 화면 — vote · revote

### 4-1. 레이아웃 (vote, 30초)

```
        누가 AI라고 생각하나요?  한 명을 지목하세요.

   ┌───────┐ ┌───────┐ ┌───────┐ ┌───────┐ ┌───────┐
   │ ①익명1 │ │ ②익명2 │ │ ③익명3 │ │ ④익명4 │ │ ⑤익명5 │
   │  [카드] │ │  [카드] │ │ ◉선택 │ │  [카드] │ │ (이탈) │
   └───────┘ └───────┘ └───────┘ └───────┘ └───────┘

              [  익명3 지목하기  →  ]     투표 3 / 4
```

- **좌석 카드 그리드.** 칸 수는 `seat_count`로 그린다 (하드코딩 금지 — CLAUDE.md).
  카드 = 좌석번호(seatColor) + 닉네임 + 큰 탭 영역.
- 탭하면 카드가 뜨고(주황 링 `#ff8a3d`, scale 1.03) 다른 카드는 살짝 눌린다(opacity 0.7).
- **하단 확정 버튼**에 대상 이름을 넣어 오지목을 줄인다("익명3 지목하기"). 누르면 잠금 —
  **재투표 불가**, 버튼이 "익명3에게 투표함 ✓"(청록)로. 조기 종료 분모(§1-2 B)에 카운트.
- 이탈(connected=false)한 자리는 **지목 가능 대상에서 뺀다**(회색 처리, 탭 불가). 자기 자신도.
  (자기 지목 허용 여부는 §7 미결정 — 기본은 **불가**로 그려둠.)

### 4-2. revote (20초, §18.3)

동점일 때만. 후보를 동점자로 좁혀 재투표.

```
        동점입니다. 후보 중 다시 지목하세요.        (20초)

        ┌───────┐   ┌───────┐
        │ ②익명2 │   │ ④익명4 │     ← 동점자만 카드로. 나머지는 흐리게 비활성
        └───────┘   └───────┘
```
- 화면 전환을 **부드럽게**: vote → revote는 배경에 얇은 붉은 플래시(0.4s) 한 번 + "동점"
  라벨. "다시 한다"의 긴장을 준다. 후보 아닌 카드는 자리에 남되 `#5b6474`로 눌러 비활성.
- **여기서도 동점이면 서버가 무작위 지목**한다(§5.2). UI는 그 결과를 §5 리빌에서 받는다.

## 5. 최후변론 화면

> ⚠️ **SPEC에 없는 신규 단계.** §7에서 A와 재조정 필요. 아래는 "vote로 지목된 한 명이
> 리빌 직전 한마디 변론한다"를 전제로 한 디자인.

### 5-1. 두 관점 — 지목된 사람 / 지켜보는 사람

이 화면은 보는 주체에 따라 **다르게** 보여야 한다. 단 **타이머·레이아웃 골격은 동일**해야
한다(I1: 지목된 게 봇이든 사람이든 화면이 같은 모양·같은 시간으로 흘러야 한다).

**(A) 내가 지목됐을 때 — 입력 주체**

```
        당신이 지목되었습니다.  마지막으로 한마디.

   ┌─────────────────────────────────────────────────────┐
   │  [ 나는 AI가 아닙니다. 왜냐하면…                    ] │
   │                                          (○/120자)  │
   └─────────────────────────────────────────────────────┘
                    [  변론 제출  ]        (0:20)
```

**(B) 남이 지목됐을 때 — 관전 주체**

```
        ③ 익명3 의 최후변론                        (0:20)

   ┌─────────────────────────────────────────────────────┐
   │                                                     │
   │   "저는 그냥 원래 말투가 이래요. 억울합니다."         │  ← 크게, 중앙
   │                                                     │
   └─────────────────────────────────────────────────────┘
              곧 정체가 공개됩니다…  ●●●
```

### 5-2. ★ I1 — 변론이 봇을 드러내지 않게

여기가 **가장 위험**하다. 지목된 게 봇이면 봇이 실시간으로 변론을 쓸 수 없다.

- **봇이 지목됐을 때도 변론은 나와야 한다.** 서버가 봇 변론을 생성해 `visible_at`에 박아
  (§5.3의 확장) 사람 변론과 **같은 타이밍 곡선**으로 노출한다. 관전 화면(B)은 사람이든
  봇이든 **동일한 "작성 중 → 등장"** 연출을 본다.
- **"작성 중 ●●●"의 지속 시간이 봇/사람에 따라 달라지면 안 된다.** 사람이 빨리 제출하면
  일찍 뜨는데, 그럼 봇은 항상 시간을 꽉 채워 "느린 쪽 = 봇"이 된다. → **모두 고정 시각에
  노출**한다(제출해도 즉시 안 띄우고 정해진 reveal 시각까지 "작성 중" 유지). 이건 §5.3의
  `visible_at` 원칙과 답변 지연 처리(target 30초 대칭, §5.3)의 논리를 그대로 따른 것이다.
- 변론 **미제출(사람이 시간 초과)**도 봇의 "혹시 실패"와 구분 안 되게: 둘 다 "변론 없음"
  중립 문구로 처리하고 화면·시간은 동일.

### 5-3. 그리고 리빌

변론 20초가 끝나면 지목된 자리의 정체가 열린다 (§18.4 승패 판정).

```
        ③ 익명3 은(는) …  🎭 연기자!            연기자 승
        ─────────────────────────────────────
        시민 승 조건: AI였다면.  이번엔 연기자였다.
```
- 정체 배지 3종: `🤖 AI` / `🎭 연기자` / `🙂 시민`. 승패 문구를 §18.4 그대로.
- 리빌은 **극적으로**: 카드가 뒤집히듯(flip 0.5s) 정체가 나오고, 승리 진영 색으로 화면 테두리
  글로우. AI 지목=시민 승, 연기자=연기자 승, 시민=AI 승.

이 UI가 실제로 돌려면 §18 상태머신 쪽에서 아래가 정리돼야 한다. **디자인만으로는 못 정한다.**

1. **발언 순번(§2)의 정의.** 현재 question은 "60초 내 전원 제출"일 뿐 강제 순번이 없다.
   레일은 `visible_at` 순서를 반영만 하도록 그렸지만, "정해진 순번으로 한 명씩"을 원한다면
   상태머신에 순번 개념을 추가해야 한다(그리고 I1 지터 설계 재검토).

3. **최후변론(§5)은 신규 페이즈다.** `vote → (최후변론) → reveal` 삽입, 20초, 봇 변론

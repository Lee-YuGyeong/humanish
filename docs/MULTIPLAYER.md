# 3D 멀티플레이 — 구조와 작업 순서

`/world` 에서 **같은 방 사람들이 한 3D 공간에 함께 있는** 부분. 게임 규칙(페이즈·투표·정체)은
여기 없다 — 그건 `docs/SPEC.md` 와 Supabase 가 맡는다. 이 문서는 **같이 있는 것**만 다룬다.

```
브라우저 A ─┐
브라우저 B ─┼─ WebSocket ─→ Worker(라우팅) ─→ RoomDO("<room_id>")   ← 방 하나 = 인스턴스 하나
브라우저 C ─┘                                     ├ 사람 소켓 N개  (좌표는 소켓 attachment)
                                                  └ 봇 아바타 M기 (서버가 100ms로 조종)
        │
        └─ 입장 티켓만 Next(같은 오리진)에서 받는다 ─→ /api/world/ticket
```

Supabase 는 **한 줄도 건드리지 않았다.** 스키마·RLS·Realtime 그대로다.

---

## 0. 왜 이 구조인가 — 결정 세 가지

### 결정 1. 별도 서버를 둔다 (SPEC §11의 의도적 예외)

SPEC 은 "별도 WebSocket 서버를 쓰지 않는다"고 못 박았다. 그걸 뒤집은 이유는 하나다.

**빈자리를 채우는 봇 아바타를 누군가의 브라우저가 대신 움직이면, 그 브라우저는 누가 봇인지 안다.**
호스트 한 명이 정답을 들고 게임하는 셈이라 게임이 성립하지 않는다 (I1).
Supabase Realtime 은 클라이언트끼리의 릴레이라 이걸 해결할 주체가 없다.

Durable Object 는 "방 하나 = 인스턴스 하나"가 공짜로 나오고, 그 안에서 서버가 봇을 조종한다.
`idFromName(room_id)` 가 같으면 어디서 접속해도 같은 인스턴스로 모이므로 **방 스코프(I10)가
구조적으로 지켜진다** — 다른 방의 이벤트는 애초에 그 인스턴스에 도달하지 않는다.

### 결정 2. 봇 좌표는 사람과 **완전히 같은 스트림**을 탄다

봇 움직임을 "A→B 로 4.2초간 이동" 같은 계획 한 건으로 보내면 대역폭은 아끼지만,
devtools 를 열면 사람(10Hz 샘플 스트림)과 봇(계획 한 줄)이 한눈에 갈린다.
SPEC §6.1 이 도착 시각 누출 때문에 Broadcast 를 버린 것과 **정확히 같은 함정**이다.

그래서 봇도 100ms 마다 한 샘플씩, "변했을 때만 보낸다"는 사람 쪽 규칙까지 그대로 따른다.
그 대가로 시뮬레이션 틱이 필요해졌다 (§4).

### 결정 3. 입장은 **서명 티켓**으로 한다

본인 확인 토큰(`players.token`)은 httpOnly 쿠키다 (SPEC §17.4). 브라우저 JS 가 읽을 수 없으니
WebSocket URL 에 실을 수 없고, 다른 오리진(워커)으로 자동 전송되지도 않는다.

같은 오리진의 `/api/world/ticket` 이 쿠키를 확인하고 **60초짜리 HMAC 티켓**을 내준다.
워커는 서명만 검증하므로 입장할 때 네트워크 왕복이 0회다 — Next 가 잠깐 죽어도 이미 들어온
사람들은 계속 논다.

## 2. 진행 순서

이 순서로 만들었고, 고칠 때도 같은 순서로 내려가면 막히지 않는다.
**계약(1)을 먼저 못 박지 않으면 나머지가 전부 두 벌이 된다.**

| # | 단계 | 끝났다는 기준 |
|---|---|---|
| 1 | **계약** — `lib/mp/protocol.ts` · `constants.ts` | 클라·워커 어느 쪽에도 상수가 복붙되지 않았다 |
| 2 | **입장 경로** — 티켓 서명/검증 | `npm test` 의 티켓 검사 통과 (위조·만료·타 비밀) |
| 3 | **방 접속** — DO 업그레이드 · 명부 교환 | 소켓 2개가 서로를 본다 (`world:verify` 1~3) |
| 4 | **이동** — 10Hz 스로틀 · 서버 검증 · 150ms 보간 | 월드 밖·NaN 이 릴레이되지 않는다 (검증 4~5) |
| 5 | **채팅** — 길이·속도 서버 검증, 본인 포함 브로드캐스트 | 검증 6 |
| 6 | **봇 조종** — 좌석 명단 조회 · 시뮬레이션 틱 | 사람 아닌 id 의 `player_moved` 가 온다 (검증 7) |
| 7 | **정리** — 하트비트 · 유령 소켓 · 빈 방 | 새로고침해도 유령이 늘지 않는다 |
| 8 | **화면** — 씬 · 아바타 · HUD | 두 브라우저에서 서로가 걸어다닌다 |

## 3. 좌표가 흐르는 길

### 송신 (10Hz + 변경 시에만)

```
useFrame(매 프레임)
  └ 값이 바뀌었나?  &&  마지막 송신에서 100ms 지났나?
       └ conn.sendMove(x, z, y, heading, anim)
```

`y` 는 **발 높이**다(눈높이가 아니다). 0 이 바닥이고 점프·가구 윗면에서만 >0 이다.
나중에 붙은 필드라 **없으면 0 으로 읽는다** — 구 클라이언트·구 워커를 끊지 않는다.
공중인지는 `y > 0` 으로 판단한다. `AnimState` 에 `'jump'` 를 넣지 않는 이유는
그 목록이 **서버 화이트리스트**라, 값을 늘리면 구 워커가 새 클라의 move 를 통째로
버려서 뛰는 동안 그 사람이 남의 화면에서 얼어붙기 때문이다.

`changed` 검사를 빼면 **가만히 서 있어도** 8인 방에서 초당 80패킷이 낭비된다.

### 서버 (검증 후 릴레이, 본인 제외)

범위(x·z·y)·유한수·애니메이션 화이트리스트만 본다. **좌표를 보정하지 않는다** —
서버가 고치면 클라와 어긋나 고무줄이 된다. 범위 밖이면 그냥 버린다.

`NaN` 하나가 통과하면 그 사람을 보는 **모든** 클라이언트의 보간이 영구히 깨진다.

### 수신 (150ms 지연 보간)

항상 최신 샘플보다 150ms 뒤를 그린다. 그래야 패킷이 한 번 늦어도 보간할 구간이 남는다.
최신 샘플을 바로 그리면 늦는 순간 아바타가 멈췄다 튄다.

**외삽하지 않는다.** 외삽은 멈춘 사람을 벽으로 밀어 넣는다.

## 4. 틱 루프에 대하여

DO 에 `setInterval` 을 두면 hibernation 이 깨져 과금이 는다. 그래서 조건을 좁혔다.

- 사람이 **1명 이상** 접속해 있고, 봇이 **1기 이상**일 때만 돈다
- 마지막 사람이 나가면 즉시 멈춘다 → 빈 방은 평소처럼 잠든다
- DO 가 evict 되어 타이머가 날아가도, 30초 알람과 다음 수신 메시지가 되살린다

**알람 슬롯은 하나뿐이다.** 유령 소켓 청소 · 시뮬레이션 복구 · 봇 좌표 저장을 한 핸들러에서
전부 처리하고 다음 알람을 직접 다시 잡는다. 사람이 0명이면 **재예약하지 않는다** —
재예약하면 빈 DO 가 영원히 주기적으로 깨어난다.

하트비트(`ping`/`pong`)는 플랫폼 auto-response 가 받으므로 DO 를 깨우지 않는다.
클라이언트는 JSON 이 아니라 raw 텍스트 `"ping"` 을 보내고, `onmessage` 는 **파싱 전에** 걸러낸다.

## 5. 서버 권위 경계

| 항목 | 권위 | 이유 |
|---|---|---|
| 좌표 · 회전 · 애니메이션 | **클라** (서버는 범위 검증만) | 반응성 우선. 틀려봐야 남의 화면에서 위치가 어긋날 뿐 |
| 좌석 · 닉네임 | **서버** (티켓 서명) | 사칭 방지. 클라가 보낸 값은 보지도 않는다 |
| 채팅 시각 · 순서 | **서버** | 모두가 같은 순서를 본다 |
| 누가 봇인가 | **서버만** | 새면 게임이 즉시 끝난다 (I1) |
| 역할 · 정체 · 페이즈 | **Supabase** | 워커는 알지도 못한다 |

경쟁 랭킹처럼 좌표 치팅이 판돈인 게임이면 좌표도 서버 권위로 올려야 한다.
그 경우 "틱 루프 최소화"가 성립하지 않으므로 DO 대신 상시 프로세스가 맞다.

## 6. 실행

```bash
cd worker && npm install     # 준비 (한 번)

# ① 워커만 검사 — Supabase도 Next도 필요 없다. wrangler dev 를 직접 띄웠다 내린다
npm run world:smoke

# ② 전체 — 진짜 방을 만들고 게임을 시작해 봇까지 확인한다
#  .env.local 하나만 채우면 된다. 워커도 --env-file 로 같은 파일을 읽는다.
#    WORLD_SHARED_SECRET, NEXT_PUBLIC_WORLD_WS_URL, 그리고 Supabase 3종
#    (Supabase 가 비어 있으면 좌석 명단이 500 → 화면엔 room_unavailable 만 뜬다)
npm run dev            # 터미널 1 — Next
npm run world:dev      # 터미널 2 — 워커
npm run world:verify   # 터미널 3 — 소켓 2개 왕복 검증

npm run world:typecheck  # 워커 타입 검사 (루트 tsc 는 worker/ 를 제외한다)
```

### 다른 컴퓨터와 같이 할 때

로컬 왕복이 되면 남은 건 **주소 세 개를 전부 공개로 바꾸는 것뿐이다.**
자세한 순서는 `worker/README.md`「다른 컴퓨터와 같이 하기」에 있고, 요점만 적으면:

```
브라우저 → Next    사람들이 여는 주소 (터널 또는 Vercel)
브라우저 → 워커    NEXT_PUBLIC_WORLD_WS_URL — 반드시 wss://
워커   → Next     NEXT_ORIGIN            — 여기서 제일 많이 막힌다
```

마지막 화살표가 함정이다. 배포된 워커는 Cloudflare 엣지에서 도니까 `127.0.0.1`은
그 컴퓨터가 아니다. 그런데 `/health`는 200, 소켓도 열린다 — **워커는 멀쩡한데 방만
비어 보인다.** 그래서 `npm run world:deploy`가 `.env.local`의 `NEXT_ORIGIN`을
`--var`로 실어 보내고, 로컬 주소면 배포 자체를 막는다.

```bash
NEXT_URL=<공개 Next 주소> npm run world:verify   # 밖에서 본 전체 왕복
```

**막히면 ①부터 본다.** ①이 통과하는데 ②가 안 되면 문제는 워커가 아니라
티켓 발급(`/api/world/ticket`)이나 좌석 명단(`/api/internal/world-room`) 쪽이다.

브라우저 두 개로 확인할 때는 **다른 프로필/시크릿 창**을 쓴다.
쿠키를 공유하면 같은 자리로 붙어 서로를 덮어쓴다.

## 7. 새로 손댈 때 주의할 것

1. **`PlayerSnapshot` 에 필드를 더할 때마다 "이걸로 봇을 골라낼 수 있나"를 먼저 묻는다.**
   `joinedAt` 같은 걸 넣으면 봇은 방 생성 시각에 뭉쳐 있어서 전부 특정된다
   (`public_players` 에서 `created_at` 이 샜던 것과 같은 사고 — SPEC §7.2).
2. **양쪽 핸들러를 같은 커밋에서 고친다.** 한쪽만 고치면 런타임에 조용히 깨진다.
3. **`PROTOCOL_VERSION` 은 의미가 바뀔 때만** 올린다. 필드 추가는 전방 호환이다.
   올렸으면 **워커를 클라이언트보다 먼저 배포한다.**
4. **메시지 크기 상한을 하나로 합치지 않는다.** 큰 페이로드가 조용히 드롭되면 원인 찾는 데
   하루가 간다. 상한에 걸려 버릴 때는 로그를 남긴다.
5. **방을 옮길 때 이전 방 상태를 전부 지운다** (`store.reset()`). 안 지우면 새어 나온다.
6. 브로드캐스트는 O(N²)다. 8인 × 10Hz = 초당 약 640 메시지 발신.
   50~100인을 노린다면 관심 영역(AoI) 필터나 배치 전송이 필요하다.

## 8. 아직 안 한 것

- **게임 페이즈와의 연결.** 워커는 페이즈를 모른다. "vote 페이즈에는 다들 앉는다" 같은 연출을
  넣으려면 `/api/internal/world-room` 이 이미 주는 `phase` 를 쓰면 되지만, 그러면 워커가
  게임 규칙을 알기 시작한다 — 넣기 전에 그게 맞는지 한 번 더 생각할 것.
- **월드 채팅과 게임 채팅의 통합.** 지금 월드 채팅은 릴레이만 하고 저장하지 않는다.
  게임의 대화 기록은 Supabase `messages` 가 따로 갖는다 (SPEC §6.1).
- **아바타 외형.** 캡슐 + 구다. `mask_id` 는 프로토콜에 이미 실려 있으니 모델만 갈아끼우면 된다.
- **재접속.** 끊기면 다시 입장 화면으로 간다. 자동 재접속은 티켓을 다시 받아야 한다(60초 만료).
